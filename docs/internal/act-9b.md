## 1. Решения R1–R20

### R1 — Строгий однопользовательский режим
- Владелец — пользователь **активной консольной сессии** в момент установки. Не учётка, от имени которой поднят инсталлятор, и не SYSTEM.
- SID владельца — в `HKLM\Software\WindowsFaceUnlock\OriginalUserSid` (запись только админ).
- Инсталлятор показывает, кто станет владельцем. Если уже записан другой — явный вопрос о смене.
- Тихая установка: `/OWNER=<DOMAIN\user или SID>`. При расхождении с записанным — отказ с ненулевым кодом, если нет `/FORCEOWNER`.
- SYSTEM и сервисные учётки владельцем быть не могут.
- SID-фильтры инсталлятора и регистратора принимают `S-1-5-21-*` и `S-1-12-1-*`.
- Сервис при старте сравнивает SID процесса с владельцем. Не совпадает — режим отказа: ping отвечает `refusing: not-owner` (R11), функции лица не работают.
- CP показывает плитку только владельцу: `ICredentialProviderCredential2::GetUserSid` + `SetUserArray`.
  - В CPUS_UNLOCK_WORKSTATION плитка есть, только если заблокированный пользователь — владелец.
  - Серверу CP доверяет, только если SID сервера = SID владельца. Правило «любой S-1-5-21» удаляется.
- Доки: «один пользователь Windows на ПК; остальные учётки входят как обычно».

### R2 — Периметр пайпа
- `PIPE_REJECT_REMOTE_CLIENTS` в режиме пайпа, включая приватные пайпы селфтестов.
- SDDL: явный запрет NETWORK `(D;;GA;;;NU)` первым ACE.
- Legacy NULL-DACL и ключи `pipe_hardened_sd`, `pipe_first_instance`, `pipe_unlock_require_system` удаляются. Поведение всегда безопасное, конфигом не отключается.
- Храповик posture удаляется вместе с этими ключами. Старый конфиг с ними даёт предупреждение «unknown key», остальное не сбрасывается (R9).
- Санитайзер подсказки в CP отбрасывает:
  - C0 и DEL;
  - C1 (U+0080–U+009F);
  - bidi-управление: U+200E–U+200F, U+202A–U+202E, U+2066–U+2069;
  - U+2028 и U+2029.
  
  Длина — не больше 120 символов.

### R3 — Плитка
- **Проверенный результат** живёт не больше 10 с и используется один раз. Он стирается при SetDeselected, UnAdvise, после ReportResult и по истечении TTL.
- **PipeCall отменяемый:** все ожидания смотрят и на событие отмены. UnAdvise и деструктор не блокируют поток LogonUI: после отмены join ограничен 1 с, дальше — безопасное отсоединение воркера с корректным владением ресурсами.
- **CPUS_LOGON:** плитка показывается только если пайп сервиса существует (мгновенная проверка) и только владельцу.
- **Тексты — честная карта причин.** Отдельный текст на каждый класс:
  - нет сохранённого пароля;
  - нет энролла;
  - камера занята;
  - слишком темно;
  - не распознано;
  - заблокировано — с секундами из `retry_after_s`;
  - сервис недоступен;
  - сохранённый пароль отклонён;
  - версии не совпадают — «обновите Face Unlock».
  
  «Unavailable» остаётся только за реальной недоступностью сервиса.
- **Локализация:** таблицы EN и RU внутри CP. Язык — из поля `lang` ответа сервиса, иначе системный язык интерфейса, иначе EN.
- **Внешний вид:** лого и подпись плитки (CPFT_TILE_IMAGE, CPFT_LARGE_TEXT «Face Unlock»).
- **Сборка CP:** `/guard:cf`, `/CETCOMPAT`, сборка не под x64 — ошибка.
- CREDUI (UAC) и RDP сознательно не поддерживаются — это пишется в доках.

### R4 — Защита от подделки
- Новые установки получают `liveness_mode="paranoid"`. Живые конфиги не трогаются. `fast` в Settings помечен как «менее безопасно».
- **Фаза 2:** вместо одного жеста — последовательность из **двух разных движений головы** из {turn_left, turn_right, nod} в случайном порядке.
  - Одна подсказка описывает оба шага по порядку, например «Turn your head left, then nod». Протокол плитки при этом не меняется.
  - Моргание больше не жест фазы 2. Пассивное моргание по-прежнему учитывается в фазе 1.
- **Неподвижность в момент подсказки:** в первые `STILLNESS_WINDOW_S = 0.4` с кадров фазы 2 межкадровые |Δyaw| и |Δpitch| ≤ `STILLNESS_MAX_DEG = 4.0`°. Иначе раунд проваливается с reason `motion-before-prompt` — это страйк.
- Порядок шагов проверяется. Каждый шаг — существующим детектором жеста с его таймаутом `GESTURE_TIMEOUT_S`. Потолок раунда = 0.4 + 2 × GESTURE_TIMEOUT_S + 2 с. `GESTURE_SEQUENCE_LEN = 2`.
- Отсчёт раунда начинается с **первого годного кадра после получения камеры**, а не до открытия.
- **Дополнительный слой.** Если доля экранных кадров среди кадров с лицом в фазе 2 ≥ SCREEN_DOUBT_FRAC, при `anti_screen=true` и sceneL ≥ low_light_luma_min — раунд проваливается с reason `screen-suspected` (страйк).
- Новые константы — в `liveness.py` с именами выше. Пересмотр — по замерам 9e.
- Селфтесты на всё перечисленное. SECURITY и README — честная модель угроз с цифрами 9a-5.

### R5 — Страйк только за настоящий провал
**Страйк:**
- no-match на кадрах с лицом;
- gesture-failed при годных кадрах;
- `motion-before-prompt`;
- `screen-suspected`.

**Не страйк:**
- ошибки движка и моделей;
- камера занята, ошибка камеры, ноль кадров;
- бёрст после буста без кадров;
- too-dark;
- deadline по вине сервиса;
- отказ custody или владельца.

### R6 — Энролл и калибровка
- **Один человек.** Каждый вектор энролла должен быть в пределах threshold (0.32) от медоиды набора. Нарушители отбрасываются с сообщением. Если осталось меньше `enroll_min_frames` — отказ.
- **Атомарная замена энролла:** сборка во временном каталоге → атомарная подмена → удаление старых файлов → запись в audit.
- **Калибровка знака поворота** — в мастере после успешного Build.
  - Пользователя просят повернуть голову влево; знак yaw сохраняется в `calibration.json` каталога данных с привязкой к имени устройства камеры.
  - Без калибровки действует прежняя константа.
  - Для замера позы нужна новая пайп-команда: SELF, только во время аренды камеры мастером.
- **Телеметрия** (лог и audit, без кадров): hf, lap, peak на попытку; базовый EAR при энролле; fps бёрста.
- **F-47 / D-40:**
  - грант после успешной фазы 2 тоже может адаптировать галерею — по прежнему правилу потолка (threshold − adaptive_margin);
  - кольцо адаптации грузится при старте независимо от warmup;
  - `adaptive_gallery` по умолчанию остаётся false.

### R7 — Модели (решение 9-02)
- buffalo_l не входит ни в бандл, ни в инсталлятор.
- Инсталлятор скачивает официальный `buffalo_l.zip` — из того же источника, что библиотека insightface. Проверяет SHA-256 по пину и распаковывает в `{app}\models\buffalo_l`.
- **Согласие.** Перед скачиванием — страница с условиями InsightFace и обязательным согласием. Тихая установка без `/ACCEPTMODELLICENSE` падает закрыто.
- **Офлайн:** `/MODELZIP=<путь>` или выбор файла на странице, проверка по тем же хэшам.
- **Единственный источник SHA** — общий модуль `face_service/model_pins.py`, его используют build.py, генерация инсталлятора и сервис.
- **Сервис в `_build_app`:** в каталоге моделей ровно пять запиненных файлов с верными SHA. Лишний файл или неверный хэш — понятный отказ, ping отвечает `refusing: no-models` (R11).
- YuNet тоже запинен; путь апстрима tauri удалён.
- **Гард сборки:** если модели попали в dist — сборка падает.

### R8 — Unicode-безопасный ввод-вывод cv2
- Чтение — `np.fromfile` + `cv2.imdecode`; запись — `cv2.imencode` + `.tofile()`.
- Результат записи проверяется.
- Селфтест на путях с кириллицей, китайскими иероглифами и `é`.

### R9 — Custody и конфиг
- **Провал custody** — недоступны все функции лица: unlock, presence, verify, энролл, адаптация.
  - Конфиг и галерею из небезопасного каталога не читаем, действуют встроенные дефолты.
  - ping отвечает `refusing: custody`; трей показывает причину и шаг исправления.
- **Поключевая деградация конфига.** Неверное значение ключа — только этот ключ получает дефолт, с громким предупреждением. Ключи безопасности получают безопасное значение.
- **Save из GUI и трея** никогда не перезаписывает файл, который не удалось разобрать: копия `.bad`, отказ с объяснением. Смена языка в трее меняет только ключ `language` и сохраняет остальное содержимое файла.
- **F-112:** если `lockout.json` не сохраняется — face unlock отказывает с `lockout-store-error`, пока сохранение не пройдёт.
- **D-69:** поддержка v1-секретов (старая энтропия) удаляется — публичных установок с v1 нет.

### R10 — Камера и presence
- **Камера по требованию.** `persistent_camera=false` по умолчанию.
  - Прогрев: при блокировке сессии сервис открывает камеру и держит её до разблокировки, но не дольше 60 с.
  - Разблокировка идёт на тёплой камере; вне этого камера закрыта.
- **Ограниченное чтение кадра** — тем же механизмом, что открытие, с потолком `camera_open_attempt_cap_s`. Зависло — захват бросается, ответ `camera-error`.
- **Буст экспозиции:** сохранять и восстанавливать `CAP_PROP_AUTO_EXPOSURE` вместе с EXPOSURE и проверять чтением. Несоответствие — буст отключается для устройства до перезапуска.
- **Камера по имени устройства.**
  - Перечисление DirectShow (совпадает с порядком CAP_DSHOW) через comtypes или хелпер; в мастере — выпадающий список.
  - Имя хранится в `camera_name` и разрешается при каждом открытии. Нет такого устройства — понятный отказ, без отката на индекс 0.
  - `camera_index` используется только при пустом `camera_name` — это миграция старых конфигов.
- **Состояние `unknown` («не вижу»).**
  - presence возвращает `unknown`, если камера занята, отключена, отдаёт чёрные кадры или арендована.
  - Монитор не считает это ни присутствием, ни отсутствием; Status и значок показывают причину.
  - Любое неизвестное ему состояние монитор тоже считает «нет решения».
  - Сервис и монитор выходят в одном релизе.
- **Детектор удалёнки.** Удалённой считается только реально управляемая сессия: SM_REMOTESESSION / SM_REMOTECONTROL, а для сторонних инструментов — маркеры активного сеанса. Простое установленное соединение не в счёт.
- **auto_lock.** По умолчанию `false`.
  - При выключенном — ни одной камерной пробы; presence только опрашивает status для уведомлений.
  - При включении пробы стартуют, при выключении камера освобождается.
- Мастер держит аренду камеры только во время съёмки и сборки.

### R11 — Watchdog и сигнал состояния
- ping отвечает `{"ok":true,"state":"serving"}` или `{"ok":true,"state":"refusing","why":"custody|not-owner|no-models|lockout-store-error"}`. Состояние refusing watchdog считает живым.
- Счётчик неудач не растёт во время паузы и обнуляется при её снятии.
- После рестарта — ожидание pong до 30 с; не дождался — рестарт неудачен.
  - Следующий рестарт — через нарастающую паузу 60 с × 2^n, потолок 30 мин.
  - Сброс после 10 мин здоровья.
- Собственная защита watchdog от второго экземпляра (мьютекс).

### R12 — Интерфейс
- **Потоки Tk:** рабочие потоки не держат ссылок на объекты Tk. Результаты — через потокобезопасную очередь, которую Tk-поток забирает по `after`.
- **DPI:** PerMonitorV2 в манифесте exe + согласованный `tk scaling`.
- **Settings:**
  - разделы «Основные» и «Для опытных» (свёрнут по умолчанию);
  - прокрутка и закреплённая панель Save / Cancel;
  - вопрос о несохранённых изменениях;
  - человеческие подписи вместо сырых енумов, ошибки валидации через i18n, разумные шаги полей;
  - порог — только в «Для опытных», границы 0.28–0.35, с предупреждением.
- **Подтверждения:** Quit, Clear пароля, Close мастера во время Replace.
- **Логи** в `.face-unlock\logs\` с миграцией старых; «Open log folder» открывает только эту папку.
- **Мастер:**
  - честный стартовый текст;
  - «Повторить», если сервис недоступен;
  - Start — только после первого годного кадра;
  - выбор камеры и шаг калибровки;
  - «Capturing i/n» не затирается;
  - в конце — реальная проверка готовности (пароль сохранён и проверен, custody в порядке, сервис видит энролл, аренда отпущена) с кнопками исправления.
- **Клавиатура:** Enter и Escape, порядок фокуса, `focus_set` во всех окнах. Ограниченная поддержка экранных дикторов (ограничение Tk) — в доках.
- **Single-instance** для трея, Settings, Status и мастера.

### R13 — Диалог пароля
- Пароль проверяется той же формой входа, что упаковывает CP: интерактивный вход через Negotiate (LogonUserW, LOGON32_LOGON_INTERACTIVE).
- Однозначный отказ (1326 и т. п.) — не сохранять. Неоднозначный ответ — сохранить с жёлтым предупреждением.
- Беспарольный режим (`DevicePasswordLessBuildVersion=2`) — объяснение и ссылка на настройку: без пароля face unlock невозможен.
- Формы имени:
  - MSA-связанная учётка — `COMPUTER\SAM` (подтверждено живьём на ПК-1);
  - Entra (S-1-12-1) — форма UPN, окончательно по VM (9e).
- Пароль, отклонённый на экране блокировки (протокол v2, `report_result`), трей показывает как «обновите сохранённый пароль».

### R14 — Уведомления
- WinRT-тосты с AppUserModelID. Ярлык в «Пуск» с этим AUMID создаёт инсталлятор, процесс трея задаёт тот же AUMID.
- Библиотека — только с лицензией MIT, BSD или Apache, с записью в THIRD_PARTY_NOTICES.
- Запасной канал — последние события в окне Status.
- Балуны pystray не используются.

### R15 — Апдейтер
- Автопроверка не чаще раза в 24 ч, в фоне.
- 404 и сетевые ошибки — молча; ручная проверка показывает всё.
- Переключатель в Settings, по умолчанию включён.
- URL репо — одна константа, её меняем в 9g.
- Установка обновлений остаётся выключенной до 9f. Потом — WinVerifyTrust + пин издателя (субъект сертификата Azure), проверка на том же хэндле файла, который запускается.

### R16 — i18n
- EN и RU — полностью, key-for-key; равенство пинится селфтестом.
- Остальные 10 языков скрыты из меню, но их коды валидны; такой конфиг показывает English.
- Все новые строки — на EN и RU: Settings, мастер, диалог пароля, инсталлятор (`[CustomMessages]` + Russian.isl).

### R17 — Установка
- Модели — R7, владелец — R1.
- **Регистрация и снятие задач** — в подписанном exe продукта: флаги `--register` / `--unregister` роутера трея, Task Scheduler COM через pywin32.
  - Сохраняется прежняя семантика: сначала graceful, затем death-wait.
  - PowerShell в установке и удалении больше не используется.
- **Каталог установки** всегда `{autopf}\WindowsFaceUnlock`.
  - `UsePreviousAppDir=no`; `/DIR=` вне Program Files — отказ.
  - До regsvr32 — проверка, что каталог пишется только админами.
  - CP регистрируется только из `{app}`.
- **Версия Windows:** `MinVersion=10.0.19045` — жёсткий пол. На сборках ниже 10.0.26100 — предупреждение «официально поддерживаются Windows 11 24H2 и 25H2».
- **Деинсталлятор:**
  - остановка задач, затем их снятие;
  - regsvr32 /u + запасное удаление ключей CP;
  - `uninsrestartdelete` для занятых файлов;
  - удаляются только свои файлы, без рекурсивного сноса произвольного каталога;
  - `RunOnceId` у всех записей [UninstallRun].
- **Коды выхода:** сбой регистрации задач — ненулевой код тихой установки.

## 2. Решения по 14 пунктам «решение нужно» и вопросам 9a-7

### 2.1 Протокол v2 (F-60, F-61, F-92, F-93) — одно изменение контракта сервис ↔ CP
- В запросах — поля `v:2` и `budget_ms` (остаток бюджета CP). Сервис использует min(свой дедлайн, `budget_ms` − 500 мс).
- **Грант** содержит одноразовый `grant_id`. После ReportResult CP отправляет `report_result {grant_id, ok}` — команда за SYSTEM-гейтом.
  - Сервис фиксирует сброс lockout и адаптацию только при `ok=true`.
  - При `ok=false` ставится постоянный флаг «сохранённый пароль отклонён», виден в трее и на плитке. Сбрасывается при сохранении нового пароля.
  - Нет `report_result` за 30 с — грант считается брошенным, ничего не фиксируется.
- CP разбирает `retry_after_s` для текста блокировки.
- ping с состоянием (R11), поле `lang` в ответах (R3).
- Разные версии протокола у CP и сервиса — плитка «обновите Face Unlock», креды не упаковываются.
- Контракт-таблица и тесты с обеих сторон.

### 2.2 Остальные пункты
